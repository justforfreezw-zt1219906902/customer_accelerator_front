# Documentation System

This directory contains the governance, planning, input, design, architecture,
traceability, quality, release, and operational records for mi-goTo Frontend.

## Directory index

| Directory | Responsibility |
| --- | --- |
| `00-governance/` | Charter, authority, ownership, policies, and completion rules |
| `01-roadmap/` | Current state, phase status, dependencies, milestones, and delivery plan |
| `02-inputs/` | Figma, backend, content, asset, environment, assumption, and constraint inputs |
| `03-design-system/` | Figma baseline, tokens, components, mappings, reviews, and deviations |
| `04-frontend/` | Frontend architecture, routes, interactions, state, content, errors, and accessibility |
| `05-backend/` | OpenAPI and backend integration documentation |
| `06-traceability/` | Links among requirements, sources, implementation, tests, and releases |
| `07-change-control/` | Change requests, issues, incidents, decisions, and human instructions |
| `08-quality/` | Acceptance criteria and test reports |
| `09-release/` | Release records and immutable release manifests |
| `10-operations/` | Environments, deployment, monitoring, support, recovery, and incidents |
| `phases/` | Authoritative scope and completion requirements for each project phase |
| `templates/` | Approved reusable documentation templates |

## Working rules

1. Read `AGENTS.md` and `VERSION.yaml` before every task.
2. Read the relevant phase document and authoritative sources before editing.
3. Preserve human-authored and unrelated content.
4. Record assumptions, unexpected events, deviations, and unresolved conflicts.
5. Keep machine-readable status registries consistent with narrative records.
6. Never mark a phase or deliverable approved without human approval evidence.
