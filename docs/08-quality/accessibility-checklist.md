# Accessibility Checklist

## Baseline

- [ ] Human-approved accessibility standard and level recorded
- [ ] Supported browser, OS, screen-reader, and device matrix recorded
- [ ] Accessibility reviewer assigned
- [ ] Exceptions use approved deviations with review dates

## Structure and semantics

- [ ] Landmarks, headings, lists, links, buttons, and forms use semantic HTML
- [ ] Page title and document language are correct for every locale
- [ ] ARIA is used only when native semantics are insufficient
- [ ] Dynamic state, expanded/collapsed state, and current route are exposed

## Keyboard and focus

- [ ] All interactions are keyboard operable
- [ ] Focus order follows visual and logical order
- [ ] Focus is visible and not obscured
- [ ] Dialog/menu/navigation focus entry and return are correct
- [ ] Anchor navigation and route changes move focus predictably
- [ ] No keyboard trap exists

## Forms and feedback

- [ ] Every field has a persistent programmatic label
- [ ] Required, format, and consent rules are understandable
- [ ] Errors are associated with fields and offer recovery
- [ ] Loading, success, and error changes are announced
- [ ] Double-submit prevention does not make status inaccessible

## Visual and responsive

- [ ] Text and non-text contrast meet the approved target
- [ ] Information does not rely on color alone
- [ ] Zoom, text resize, reflow, and orientation behavior are verified
- [ ] Target sizes and spacing meet approved requirements
- [ ] Motion respects reduced-motion preference
- [ ] Images have appropriate alternatives or decorative treatment

## Evidence

- [ ] Automated results attached
- [ ] Manual keyboard review attached
- [ ] Screen-reader review attached where required
- [ ] Zoom/reflow and contrast evidence attached
- [ ] Findings linked to Issues or approved Deviations
- [ ] Human review recorded
