# Milestone Plan

## Planning assumptions

Dates, effort, staffing, and release targets remain unset until Phase 0 confirms
inputs and ownership. Milestones are evidence gates, not calendar promises.

| Milestone | Included phases | Exit evidence | Human approval |
| --- | --- | --- | --- |
| M0 — Audit readiness | Phase 0 | Source inventory, gaps, risks, dependencies, and Phase 1 readiness recommendation | Phase 0 reviewer |
| M1 — Frontend foundation | Phase 1 | Approved toolchain, shell, boundaries, and working validation commands | Product owner / Tom |
| M2 — Visual foundation | Phases 2–3 | Traceable Tokens and accessible Core Components | Design reviewer / colleague |
| M3 — Component system | Phases 4A–4C | Composite, Product, and Section layers with dependency evidence | Design reviewer for Composite; product owner for Product/Sections |
| M4 — Interaction baseline | Phase 5 | Approved route, link, CTA, form, success, and error map | Product owner / Tom |
| M5 — Static website | Phases 6A–6E | Reviewed responsive pages using approved content | Design reviewer and product owner |
| M6 — Integrated lead flow | Phase 7 | OpenAPI-aligned submission with runtime and recovery evidence | Backend owner and product owner |
| M7 — Release readiness | Phase 8 | QA evidence, release manifest, deployment, monitoring, and rollback readiness | Product owner / Tom |

## Scheduling rules

- Assign dates only after required inputs and owners are confirmed.
- Parallel work is allowed only when the dependency map shows no unresolved
  coupling and human owners accept the risk.
- Legal pages require approved legal content.
- Backend integration requires an assigned official backend API version and
  authoritative OpenAPI.
- Production deployment requires explicit human authorization.
